# Post-Mortem Standard (v1)

> **Instruction to Claude:** If this file is in a project, the project ends with a **comprehensive
> post-mortem**. From the first session, keep the session journal (§3). When the final phase is complete
> (§2), run the post-mortem procedure in §4 without being asked: mine the evidence, analyze the whole
> process across Claude Code and Cowork, audit every observation, evaluate every recommendation, and
> deliver the result as a PDF (`docs/postmortem/POSTMORTEM-<date>-r<rev>.pdf`). Nobody has to ask again.
> If `docs/postmortem/findings.json` already exists, continue from it instead of starting over.

---

## 1. What it is

A structured review of **how** the project was done, not just what was delivered. It looks for process
inefficiencies, logical errors, wrong assumptions, rework, wasted usage, missing tools, environment
friction, communication gaps, and weaknesses in the standards themselves (including this folder's
ai-assets), and turns them into ranked, evaluated recommendations.

Three rules make it trustworthy:

1. **Evidence first.** Every observation cites concrete evidence: a commit, a file, a transcript
   signal, a journal entry, a plan task, a metric or something the user said.
2. **Everything is audited.** Every observation is checked by an auditor who tries to disprove it, and
   gets a verdict (*confirmed / plausible / rejected*) with a confidence. Rejected observations stay in
   the report, in an appendix, with the reason.
3. **Nothing is left unexamined.** Every machine-detected signal is either tied to a finding or
   explicitly dismissed with a reason. The PDF can't be generated until that's true.

| Piece | Path | Role |
|---|---|---|
| Post-mortem script | `scripts/postmortem.mjs` | Copied **verbatim** from §11. Mines evidence, validates, renders the PDF. |
| Session journal | `docs/postmortem/JOURNAL.md` | One line per session, both surfaces, kept **during** the project (§3). |
| Metrics | `docs/postmortem/metrics.json` | Generated by `mine`. Never hand-edited. |
| Findings register | `docs/postmortem/findings.json` | Written by Claude during the post-mortem (§9). The single source for the report. |
| Report | `docs/postmortem/POSTMORTEM-<end-date>-r<rev>.pdf` | Generated by `report`. Never written by hand. |

## 2. Trigger

Run the post-mortem when **any** of these is true:

- Every task in the final phase of `docs/PLAN.md` is ticked (the Progress Bar Standard shows 100%).
- The user says the project is done, shipped, handed over, or abandoned.
- The user asks for a post-mortem or retrospective (a mid-project one is fine; mark it
  `"subtitle": "Interim review"`).

The post-mortem is **not** a task in `PLAN.md` (it would stop the plan ever reaching 100%). It runs
right after. Projects that span several Claude surfaces get **one** post-mortem covering all of them.

Where to run it: wherever the repo and transcripts are. In **Claude Code**, run it in the project
session. In **Cowork**, run it from the folder linked to the project; if Claude Code transcripts aren't
reachable from there, run `mine --no-transcripts` and note the gap in `methodNotes`. `postmortem.mjs`
runs on the host: it only reads records and executes no project code, so it's allowed under the VM Lab
Standard.

## 3. During the project: the session journal

Cowork sessions leave no transcripts on disk, and memory of a session fades fast, so the evidence has
to be captured as the work happens. **At the end of every working session** (and at every checkpoint in
the Token Usage Standard), append one line to `docs/postmortem/JOURNAL.md`:

```markdown
- 2026-11-04 · cowork · S7 · did: drafted API docs, fixed auth bug · issues: lab VM DNS broke, 25 min · corrections: user wanted OpenAPI, not prose
- 2026-11-05 · claude-code · S8 · did: phase 3 tasks 3.1–3.4 · issues: none · corrections: none
```

Format: `- <YYYY-MM-DD> · <surface> · S<n> · did: … · issues: … · corrections: …`, with `·` separators.
Surface is `claude-code`, `cowork`, or another surface name. Write `none` for an empty field.

- **issues:** anything that cost time or went wrong: failed tools, blocked steps, wrong assumptions,
  retries, environment problems. Include the rough time lost.
- **corrections:** every time the user redirected, rejected or corrected the work, in a few words.
  These are the most valuable post-mortem evidence; never omit them.
- One line, honest, no padding. It costs a few tokens per session and is the only record of Cowork work.

Create the file with a `# Journal` heading the first time. `mine` turns every entry with a real
`issues` or `corrections` value into a signal.

## 4. Procedure

Track these steps as a task list, so the user can follow along.

**Step 1: Freeze and scope.**
Commit all work. Confirm the trigger (§2). Note the period (first to last working day), the surfaces
used, and any standards present in the project (Progress Bar, Token Usage, VM Lab, others).

**Step 2: Mine.**
Copy §11 to `scripts/postmortem.mjs` (verbatim) and run `node scripts/postmortem.mjs mine`. It reads:

| Source | What it yields |
|---|---|
| Claude Code transcripts (`~/.claude/projects/<repo-slug>/**/*.jsonl`, auto-detected; override with `--transcripts DIR`, repeatable) | Sessions, models, tokens (input/output/cache), tool calls and errors, user interrupts, subagent sessions |
| `git log` | Commits, reverts, fix-type commits, most-changed files |
| `docs/PLAN.md` | Phases, tasks, tasks still open |
| `docs/postmortem/JOURNAL.md` | Session history for every surface, issues and corrections |

It emits **signals**: re-reading the same file, repeating the same command, streaks of failing tool
calls, high error rates, long idle gaps (expired prompt cache), user interrupts, heavy sessions, large
subagent fan-out, edit churn, reverts, open tasks, journal issues and corrections, missing journal.
Signals are **leads, not findings**. Use `--since YYYY-MM-DD` if the transcript folder also holds older,
unrelated work.

**Step 3: Reconstruct the timeline.**
From git, the journal, `docs/USAGE-PLAN.md` (log and handoffs), `docs/LAB.md` (log) and the plan, build
a short dated timeline of what actually happened, including detours. Compare it with the plan: which
phases ran long, which were reordered, what scope was added or dropped. Put the key events in
`findings.json` → `timeline`.

**Step 4: Analyze through every lens (§5).**
Go through each lens deliberately, even ones that seem irrelevant. Investigate every signal by reading
the cited transcript region, commit or file (narrowly: line ranges, not whole transcripts). Draft
observations, each with its evidence. Look for patterns as well as incidents: three small retries of
the same kind are one finding about a missing tool or check.

**Step 5: Audit every observation (§6).**
Each observation goes to an auditor whose job is to disprove it. Record verdict, confidence, method and
the counter-evidence sought.

**Step 6: Evaluate every recommendation (§7).**
Confirmed and plausible findings get one or more recommendations, each with target, benefit, effort,
risk, alternatives considered and reasoning. The script computes score and priority.

**Step 7: Disposition every signal.**
In `findings.json` → `signalDispositions`, map **every** signal id to a finding id, or to
`noise: <reason>`, `expected: <reason>` or `duplicate: <reason>`.

**Step 8: Validate and render.**
`node scripts/postmortem.mjs check` until it passes, then `node scripts/postmortem.mjs report`. Then
**open the PDF and look at it**: read the executive summary, page through the findings, and confirm
nothing is cut off and nothing sensitive is visible. The renderer redacts common secret formats, but
it's not a guarantee.

**Step 9: Deliver.**
- Commit `docs/postmortem/` (journal, metrics, findings, report.html, PDF).
- **Cowork:** send the PDF to the user as a file. **Claude Code:** give the path.
- Tell the user in 3–6 lines: the headline (what most limited the project), the P1 recommendations,
  and the number of findings by verdict. Don't restate the report.

**Step 10: Follow through.**
Ask the user which recommendations to accept. Record each answer in the recommendation's `decision`
(`accepted / declined / deferred`, with an optional `decisionNote`). Then:
- `project` / `claude-md` → apply in this repo now.
- `standard:<NAME>` → edit that standard in the shared ai-assets folder, bump its version
  (v1 → v1.1), and keep its verbatim scripts in sync. Ask before editing shared assets.
- `new-standard:<NAME>` → draft it in the ai-assets folder following these conventions, after the
  user agrees.
- `tool:<name>` → write it per the Token Usage Standard §5 (project-local first, promote when a second
  project needs it).
- `workflow` / `user` → state them plainly to the user; they're habits, not files.

When applied, set `decision` to `done`, bump `revision`, and re-run `report`. A new PDF
(`-r2`) is the record of what changed.

## 5. Analysis lenses

| Lens (`category`) | Questions to answer | Typical evidence |
|---|---|---|
| Process efficiency (`efficiency`) | Where did time go that didn't move the plan forward? Waiting, retries, rework, detours, steps done in the wrong order, work done twice? | Error streaks, repeat commands, re-reads, idle gaps, timeline vs plan |
| Logic & correctness (`logic`) | Which assumptions turned out wrong? Which bugs were introduced and later fixed, and why weren't they caught earlier? Any decision that was reversed? Any reasoning that contradicted the evidence at the time? | Reverts, fix commits, edit churn, journal corrections |
| Planning & scope (`plan`) | Was the plan right-sized? Which phases ran long or were reordered? What scope crept in or was dropped? Were tasks well-defined enough to finish in one pass? | PLAN.md history (`git log -p docs/PLAN.md`), open tasks, timeline |
| Token & usage (`usage`) | Was each task on the right model tier? Were agents used well (or too much)? Were context-heavy reads avoidable? Did sessions hit limits mid-task? | Tokens per session, heavy sessions, agent fan-out, USAGE-PLAN estimates vs actuals |
| Tooling & automation (`tooling`) | What was done by hand three or more times that should be a script? Which existing tools were slow, flaky or missing? | Repeat commands, journal issues, Token Usage Standard tool log |
| Environment & lab (`environment`) | Did the VM/LXC lab, network, host or dependencies cause friction? Was the guest type right? | Error streaks on virsh/ssh, LAB.md log, journal issues |
| Communication & handoffs (`communication`) | Where did Claude misunderstand the user, or the user have to correct or repeat themselves? Were handoffs between sessions and surfaces (Claude Code ↔ Cowork) lossy? | Journal corrections, interrupts, handoff notes vs next-session behavior |
| Quality & testing (`quality`) | Were tests written and run at the right time? What escaped to the user before being caught? Was verification real (ran it) or assumed (read it)? | Fix commits after "done", test commands, revert timing |
| Standards & ai-assets (`standards`) | Did each standard present in the project help, hinder, or get ignored? What's missing from them? Any conflict between two standards? | All of the above, traced to a standard's section |

Severity scale (`impact.severity`): **1** cosmetic · **2** minor friction (minutes) · **3** noticeable
cost (an hour, one redo) · **4** major cost (a session or more, user-visible defect) · **5** project
outcome affected (wrong deliverable, data loss, security issue, missed deadline). Severity ≥4 needs at
least two independent evidence items.

## 6. Audit rules

- **Independent by default.** For each batch of related observations, spawn a reviewer subagent. Give
  it the **evidence references and the claim to test**, not your reasoning. Brief it: *"Try to disprove
  this. Read the cited evidence and anything nearby that could contradict it. Return verdict, confidence
  0–100, method, and what you checked that could have disproved it."* Use `opus` for severity ≥4 or
  logic findings, `sonnet` otherwise, and `haiku` for simple metric-based checks. Batch 3–5 observations
  per reviewer.
- **When no subagent is available** (a surface without agents), do a separate adversarial pass after
  drafting all observations, set `"independent": false`, and accept the confidence cap of 70 (enforced).
- **Verdicts:**
  - `confirmed`: the evidence holds and no counter-evidence was found. Confidence ≥ 70.
  - `plausible`: supported but not proven, e.g. confounded data or a single source. Any confidence.
  - `rejected`: disproved, or the evidence doesn't support it. Keep it; it goes to Appendix A.
- **`counterEvidence` is never empty.** It states what was checked that could have disproved the
  observation, and what was found, even if that's "searched X and Y; nothing contradicts it".
- **Don't audit your own blame away, or inflate it.** Findings about Claude's own mistakes are reported
  as plainly as anything else. Findings about the user's choices are worded as process observations
  ("requirements arrived after phase 2 started"), never as criticism.
- The auditor may **re-scope** a finding (lower severity, change category, split it). Record that in
  `method`.

## 7. Evaluation and scoring

Every recommendation must have:

| Field | Meaning |
|---|---|
| `action` | One sentence a person or Claude could act on directly |
| `target` | Where it lands: `project`, `claude-md`, `workflow`, `user`, `standard:<NAME>`, `new-standard:<NAME>`, `tool:<name>` |
| `benefit` 1–5 | How much future cost it removes (5 = eliminates a severity-4+ class of problem) |
| `effort` 1–5 | Cost to implement (1 = one-line change, 5 = multi-session project) |
| `risk` | What could get worse: side effects, extra overhead, new failure modes |
| `alternatives` | At least one other option considered (including "do nothing" where reasonable) |
| `evaluation` | Why this option beats the alternatives, in a sentence or two |
| `decision` | `proposed` until the user decides (§4 step 10) |

**Score** = severity × benefit × (confidence ÷ 100) ÷ effort, rounded to 0.1.
**Priority:** P1 ≥ 5 · P2 ≥ 2 · P3 below 2. The script computes both; never hand-set them.

Prefer recommendations that remove a **class** of problem (a check, a tool, a standard change) over
ones that patch a single incident. Prefer changing a standard or tool over "be more careful".

## 8. Report spec (generated)

`report` renders a US Letter PDF from `findings.json` + `metrics.json`, styled to match the Progress
Bar Standard (italic serif headings, maroon brand, mono labels), with page numbers. Sections:

1. **Cover:** project, period, surfaces, findings by verdict, recommendations by priority, signals
   reviewed, revision, standard version.
2. **Executive summary:** `summary` (2–3 short paragraphs: headline, main causes, what to change),
   plus the top six recommendations.
3. **Project at a glance:** sessions, tokens, tool calls, error rate, git, plan and journal figures,
   tool-use table, most-changed files, timeline.
4. **Method:** fixed text explaining evidence, lenses, audit, scoring and completeness, plus
   `methodNotes` (limits of the data, e.g. Cowork reconstructed from the journal).
5. **Findings:** grouped by lens. Each card shows observation, impact, evidence, root cause, the audit
   box, and every recommendation with its full evaluation.
6. **Recommendation register:** all recommendations ranked by score.
7. **Appendix A:** rejected observations and why.
8. **Appendix B:** every signal and its disposition.
9. **Appendix C:** session list.

PDF rendering uses, in order: `PM_BROWSER` (path to a Chromium-family browser), then `chromium`,
`chromium-browser`, `google-chrome`, `google-chrome-stable`, `microsoft-edge`, `brave-browser` on
`PATH`, then Playwright if the project has it installed. The browser renders from a temporary folder in
the home directory, so snap/flatpak browsers work. If none is available, `report --html-only` writes
`report.html`; open it in any browser and Print → Save as PDF (Letter, background graphics on).


Field rules (enforced by `check`):
- `id` `PM-NNN`, unique. Recommendation ids `PM-NNN-RN`.
- `category` is one of the §5 lens keys. Evidence `type` is one of `commit`, `file`, `transcript`,
  `session`, `plan`, `journal`, `log`, `metric`, `signal`, `user`, `artifact`. A `signal` ref must exist
  in `metrics.json`.
- Rejected findings need no `rootCause` or recommendations, but do need the full `audit`.
- Every signal in `metrics.json` has a disposition, and no disposition points at a missing signal or
  finding. If `mine` is re-run, re-check the dispositions: signal ids are renumbered.
- Quote evidence briefly (≤ ~200 characters). Never paste secrets, credentials or personal data into
  the register.

## 10. Ongoing obligations

1. From the first session: keep `JOURNAL.md` (§3), one line per session, on every surface.
2. When the trigger fires (§2), run §4 in full. Don't shorten the audit or skip lenses because the
   project went well; a clean post-mortem is a valid result and still needs its evidence.
3. Keep the post-mortem itself proportionate: one or two sessions. Delegate transcript reading and
   audits to subagents, and read line ranges, not whole transcripts (Token Usage Standard §7).
4. After the user decides on recommendations, apply the accepted ones, bump `revision`, and regenerate.
5. When a recommendation changes a shared standard, note the post-mortem as the reason in that
   standard's change (commit message or a changelog line).

```js
    }
  }
  for (const c of s.calls) { c.error = results.get(c.id) === true; if (c.error) s.toolErrors++; }
  s.stamps.sort((a, b) => a - b);
  s.start = s.stamps[0] ?? null; s.end = s.stamps.at(-1) ?? null;
  return s;
}
function parsePlan(file) {
  if (!fs.existsSync(file)) return null;
  let phase = null; const phases = [];
  for (const line of fs.readFileSync(file, 'utf8').split('\n')) {
    const h = line.match(/^#{2,3}\s+Phase\s+(\d+)\s*[—–:-]\s*(.+)$/i);
    if (h) { phase = { n: +h[1], title: h[2].trim(), total: 0, done: 0 }; phases.push(phase); continue; }
    const t = line.match(/^- \[( |x|X)\]\s+/);
    if (t && phase) { phase.total++; if (t[1] !== ' ') phase.done++; }
  }
  const total = phases.reduce((a, p) => a + p.total, 0), done = phases.reduce((a, p) => a + p.done, 0);
  return { file: path.relative(ROOT, file), phases: phases.length, total, done, open: total - done };
}
function parseJournal(file) {
  if (!fs.existsSync(file)) return null;
  const entries = fs.readFileSync(file, 'utf8').split('\n').filter((l) => /^- \d{4}-\d{2}-\d{2}/.test(l)).map((l) => {
    const f = (k) => (l.match(new RegExp(`${k}:\\s*([^·]*)`, 'i')) || [])[1]?.trim() || '';
    return { line: l, date: l.slice(2, 12), surface: (l.split('·')[1] || '').trim(), issues: f('issues'), corrections: f('corrections') };
  });
  const isReal = (v) => !!v && !/^(none|n\/a|-|—)$/i.test(v);
  return { file: path.relative(ROOT, file), entries: entries.length, surfaces: [...new Set(entries.map((e) => e.surface).filter(Boolean))],
    withIssues: entries.filter((e) => isReal(e.issues) || isReal(e.corrections)).map((e) => ({ date: e.date, surface: e.surface, issues: isReal(e.issues) ? e.issues : '', corrections: isReal(e.corrections) ? e.corrections : '' })) };
}
function gitStats(sinceStr) {
  if (run('git', ['rev-parse', '--is-inside-work-tree']) === null) return null;
  const sinceArg = sinceStr ? [`--since=${sinceStr}`] : [];
  const log = run('git', ['log', ...sinceArg, '--date=iso-strict', '--pretty=format:%H%x09%ad%x09%s']) || '';
  const commits = log.split('\n').filter(Boolean).map((l) => { const [h, d, ...s] = l.split('\t'); return { hash: h.slice(0, 9), date: d, subject: s.join('\t') }; });
  const churn = {};
  for (const l of (run('git', ['log', ...sinceArg, '--numstat', '--pretty=tformat:']) || '').split('\n')) {
    const [a, d, f] = l.split('\t'); if (!f) continue; churn[f] = (churn[f] || 0) + (+a || 0) + (+d || 0);
  }
  return { commits: commits.length, first: commits.at(-1)?.date || null, last: commits[0]?.date || null,
    reverts: commits.filter((c) => /^Revert\b/.test(c.subject)), fixes: commits.filter((c) => /\b(fix(es|ed)?|fixup!?|hotfix|oops|typo|wip)\b/i.test(c.subject)).length,
    topChurn: Object.entries(churn).sort((a, b) => b[1] - a[1]).slice(0, 10).map(([file, lines]) => ({ file, lines })) };
}
function cmdMine() {
  const sinceStr = opt('--since');
  const since = sinceStr ? Date.parse(sinceStr) : null;
  const dirs = transcriptDirs();
  const sessions = dirs.flatMap((d) => (fs.existsSync(d) ? walk(d) : [])).map((f) => mineTranscript(f, since)).filter((s) => s.stamps.length);
  const signals = []; const add = (kind, weight, detail, session) => signals.push({ kind, weight, detail: clip(redact(detail), 200), session: session || null });
  const tools = {}; const edits = {};
  for (const s of sessions) {
    const reads = {}, cmds = {};
    for (const c of s.calls) {
      tools[c.name] ??= { calls: 0, errors: 0 }; tools[c.name].calls++; if (c.error) tools[c.name].errors++;
      const fp = c.input.file_path || c.input.notebook_path || c.input.path;
      if (c.name === 'Read' && fp) reads[fp] = (reads[fp] || 0) + 1;
      if (/^(Edit|Write|MultiEdit|NotebookEdit)$/.test(c.name) && fp) edits[fp] = (edits[fp] || 0) + 1;
      if (c.name === 'Bash' && c.input.command) { const k = c.input.command.trim(); cmds[k] = (cmds[k] || 0) + 1; }
    }
    for (const [f, n] of Object.entries(reads)) if (n >= 3) add('reread', n, `Read ${rel(f)} ${n}× in one session`, s.id);
    for (const [k, n] of Object.entries(cmds)) if (n >= 3) add('repeat-command', n, `Ran \`${k}\` ${n}× in one session`, s.id);
    let streak = 0, streakStart = null;
    for (const c of [...s.calls, { error: false }]) {
      if (c.error) { if (!streak) streakStart = c; streak++; continue; }
      if (streak >= 3) add('error-streak', streak, `${streak} consecutive failed tool calls starting with ${streakStart.name}: ${JSON.stringify(streakStart.input)}`, s.id);
      streak = 0;
    }
    for (let i = 1; i < s.stamps.length; i++) { const gap = (s.stamps[i] - s.stamps[i - 1]) / 60000; if (gap > 60) add('idle-gap', Math.round(gap / 60), `Idle ${Math.round(gap)} min mid-session (prompt cache expired) at ${new Date(s.stamps[i - 1]).toISOString()}`, s.id); }
    if (s.interrupts) add('interrupt', s.interrupts * 2, `User interrupted ${s.interrupts}× (possible wrong direction)`, s.id);
    const errRate = s.calls.length ? s.toolErrors / s.calls.length : 0;
    if (s.calls.length >= 20 && errRate > 0.15) add('error-rate', Math.round(errRate * 20), `${Math.round(errRate * 100)}% of ${s.calls.length} tool calls failed`, s.id);
    const agents = (s.tools.Task || 0) + (s.tools.Agent || 0);
    if (agents > 10) add('agent-fanout', Math.round(agents / 5), `${agents} subagents spawned in one session`, s.id);
  }
  for (const [f, n] of Object.entries(edits)) if (n >= 6) add('edit-churn', Math.round(n / 3), `${rel(f)} edited ${n}× across the project`);
  const tot = (s) => s.tokens.input + s.tokens.output + s.tokens.cacheRead + s.tokens.cacheWrite;
  const main = sessions.filter((s) => !s.subagent), med = median(main.map(tot));
  if (main.length >= 3) for (const s of main) if (tot(s) > 2 * med) add('heavy-session', Math.round(tot(s) / med), `Session used ${fmtInt(tot(s))} tokens (${(tot(s) / med).toFixed(1)}× median)`, s.id);
  const git = gitStats(sinceStr);
  for (const r of git?.reverts || []) add('revert', 3, `Revert commit ${r.hash}: ${r.subject}`);
  const plan = parsePlan(path.join(ROOT, 'docs/PLAN.md'));
  if (plan?.open) add('open-tasks', plan.open, `${plan.open} plan task(s) still unticked at post-mortem time`);
  const journal = parseJournal(path.join(PM_DIR, 'JOURNAL.md'));
  for (const e of journal?.withIssues || []) add('journal-issue', 3, `${e.date} ${e.surface}: ${[e.issues && 'issue: ' + e.issues, e.corrections && 'correction: ' + e.corrections].filter(Boolean).join(' / ')}`);
  if (!journal) add('no-journal', 5, 'docs/postmortem/JOURNAL.md missing: session history for non-Claude-Code work must be reconstructed');
  if (!sessions.length) add('no-transcripts', 2, 'No Claude Code transcripts found (Cowork-only project, or wrong --transcripts dir)');
  signals.sort((a, b) => b.weight - a.weight || a.kind.localeCompare(b.kind) || a.detail.localeCompare(b.detail));
  signals.forEach((s, i) => (s.id = `S-${String(i + 1).padStart(3, '0')}`));
  const totals = sessions.reduce((t, s) => { for (const k in s.tokens) t.tokens[k] += s.tokens[k]; t.calls += s.calls.length; t.errors += s.toolErrors; t.interrupts += s.interrupts; t.userMsgs += s.userMsgs; return t; },
    { tokens: { input: 0, output: 0, cacheRead: 0, cacheWrite: 0 }, calls: 0, errors: 0, interrupts: 0, userMsgs: 0 });
  const out = { standard: `POST-MORTEM-STANDARD ${VERSION}`, generated: new Date().toISOString(), root: ROOT, since: sinceStr || null, transcriptDirs: dirs,
    totals: { ...totals, sessions: main.length, subagentSessions: sessions.length - main.length, start: Math.min(...sessions.map((s) => s.start)) || null, end: Math.max(...sessions.map((s) => s.end)) || null },
    tools, git, plan, journal,
    sessions: sessions.map((s) => ({ id: s.id, surface: s.surface, subagent: s.subagent, start: s.start && new Date(s.start).toISOString(), end: s.end && new Date(s.end).toISOString(),
      minutes: s.start ? Math.round((s.end - s.start) / 60000) : 0, models: [...s.models], tokens: s.tokens, toolCalls: s.calls.length, toolErrors: s.toolErrors, interrupts: s.interrupts, userMsgs: s.userMsgs })),
    signals };
  if (!Number.isFinite(out.totals.start)) out.totals.start = out.totals.end = null;
  fs.mkdirSync(PM_DIR, { recursive: true });
  fs.writeFileSync(METRICS, JSON.stringify(out, null, 2));
  const T = totals.tokens;
  console.log(`mine: ${main.length} sessions (+${out.totals.subagentSessions} subagent) · ${fmtInt(totals.calls)} tool calls · ${fmtInt(totals.errors)} errors · ${fmtInt(T.input + T.output + T.cacheRead + T.cacheWrite)} tokens · git ${git ? git.commits + ' commits' : 'n/a'} · plan ${plan ? plan.done + '/' + plan.total : 'n/a'} · journal ${journal ? journal.entries : 'missing'}`);
  console.log(`mine: ${signals.length} signals → ${path.relative(ROOT, METRICS)}`);
  for (const s of signals.slice(0, 12)) console.log(`  ${s.id} ${s.kind.padEnd(15)} ${s.detail}`);
  if (signals.length > 12) console.log(`  … ${signals.length - 12} more in metrics.json`);
}

const score = (f, r) => Math.round(((f.impact.severity * r.benefit * (f.audit.confidence / 100)) / r.effort) * 10) / 10;
const priority = (s) => (s >= 5 ? 'P1' : s >= 2 ? 'P2' : 'P3');
function validate(F, M) {
  const errs = []; const e = (where, msg) => errs.push(`${where}: ${msg}`);
  const str = (v, min = 1) => typeof v === 'string' && v.trim().length >= min;
  const int = (v, lo, hi) => Number.isInteger(v) && v >= lo && v <= hi;
  if (!str(F.project)) e('root', 'project is required');
  if (!F.period || !/^\d{4}-\d{2}-\d{2}$/.test(F.period.start || '') || !/^\d{4}-\d{2}-\d{2}$/.test(F.period.end || '')) e('root', 'period.start/end must be YYYY-MM-DD');
  if (!Array.isArray(F.surfaces) || !F.surfaces.length) e('root', 'surfaces[] required (claude-code, cowork, …)');
  if (!str(F.summary, 80)) e('root', 'summary must be at least 80 characters');
  if (!int(F.revision ?? 1, 1, 99)) e('root', 'revision must be an integer 1–99');
  if (!Array.isArray(F.findings) || !F.findings.length) { e('root', 'findings[] must not be empty'); return errs; }
  const ids = new Set();
  for (const f of F.findings) {
    const w = f.id || '(no id)';
    if (!/^PM-\d{3}$/.test(f.id || '')) e(w, 'id must look like PM-001'); else if (ids.has(f.id)) e(w, 'duplicate id'); ids.add(f.id);
    if (!CATEGORIES[f.category]) e(w, `category must be one of ${Object.keys(CATEGORIES).join(', ')}`);
    for (const k of ['title', 'observation']) if (!str(f[k], k === 'observation' ? 40 : 5)) e(w, `${k} missing or too short`);
    if (!f.impact || !int(f.impact.severity, 1, 5) || !str(f.impact.cost)) e(w, 'impact.severity (1–5) and impact.cost required');
    const ev = Array.isArray(f.evidence) ? f.evidence : [];
    if (!ev.length) e(w, 'at least one evidence item required');
    if (f.impact?.severity >= 4 && ev.length < 2) e(w, 'severity ≥4 needs at least two independent evidence items');
    ev.forEach((x, i) => { if (!EVIDENCE_TYPES.includes(x.type)) e(`${w} evidence[${i}]`, `type must be one of ${EVIDENCE_TYPES.join(', ')}`); if (!str(x.ref)) e(`${w} evidence[${i}]`, 'ref required'); if (x.type === 'signal' && M && !M.signals.some((s) => s.id === x.ref)) e(`${w} evidence[${i}]`, `unknown signal ${x.ref}`); });
    const a = f.audit || {};
    if (!VERDICTS.includes(a.verdict)) e(w, `audit.verdict must be ${VERDICTS.join('/')}`);
    for (const k of ['auditor', 'method']) if (!str(a[k], 5)) e(w, `audit.${k} required`);
    if (!str(a.counterEvidence, 20)) e(w, 'audit.counterEvidence required: what was checked that could disprove this, and what was found');
    if (typeof a.independent !== 'boolean') e(w, 'audit.independent (true/false) required');
    if (!int(a.confidence, 0, 100)) e(w, 'audit.confidence must be an integer 0–100');
    if (a.independent === false && a.confidence > 70) e(w, 'self-audited findings are capped at confidence 70');
    if (a.verdict === 'confirmed' && a.confidence < 70) e(w, 'confirmed needs confidence ≥70 (else use plausible)');
    if (a.verdict === 'rejected') continue;
    if (!str(f.rootCause, 20)) e(w, 'rootCause required for confirmed/plausible findings');
    const recs = Array.isArray(f.recommendations) ? f.recommendations : [];
    if (!recs.length) e(w, 'at least one recommendation required');
    recs.forEach((r, i) => {
      const rw = r.id || `${w} rec[${i}]`;
      if (!new RegExp(`^${f.id}-R\\d+$`).test(r.id || '')) e(rw, `id must look like ${f.id}-R1`); else if (ids.has(r.id)) e(rw, 'duplicate id'); ids.add(r.id);
      if (!str(r.action, 15)) e(rw, 'action required');
      if (!TARGET_RE.test(r.target || '')) e(rw, 'target must be project | claude-md | workflow | user | standard:<NAME> | new-standard:<NAME> | tool:<name>');
      if (!int(r.benefit, 1, 5) || !int(r.effort, 1, 5)) e(rw, 'benefit and effort must be integers 1–5');
      for (const k of ['risk', 'alternatives', 'evaluation']) if (!str(r[k], 10)) e(rw, `${k} required (evaluate it, don't leave it blank)`);
      if (!DECISIONS.includes(r.decision)) e(rw, `decision must be ${DECISIONS.join('/')}`);
    });
  }
  if (M) {
    const disp = F.signalDispositions || {};
    for (const s of M.signals) {
      const d = disp[s.id];
      if (!d) e(s.id, `signal not dispositioned (${s.kind}: ${clip(s.detail, 60)})`);
      else if (/^PM-\d{3}$/.test(d)) { if (!ids.has(d)) e(s.id, `disposition points to unknown finding ${d}`); }
      else if (!/^(noise|expected|duplicate):\s*\S.{9,}/.test(d)) e(s.id, 'disposition must be a finding id or "noise: <reason>", "expected: <reason>", "duplicate: <reason>"');
    }
    for (const k of Object.keys(disp)) if (!M.signals.some((s) => s.id === k)) e(k, 'disposition for a signal that is not in metrics.json (re-run mine?)');
  }
  return errs;
}
function load(file) {
  const fp = path.resolve(file || FINDINGS);
  if (!fs.existsSync(fp)) { console.error(`postmortem: missing ${path.relative(ROOT, fp)} (see POST-MORTEM-STANDARD §9)`); process.exit(2); }
  const F = readJSON(fp);
  const mp = path.resolve(ROOT, F.metrics || path.relative(ROOT, METRICS));
  const M = fs.existsSync(mp) ? readJSON(mp) : null;
  return { F, M, fp };
}
function cmdCheck(quiet) {
  const { F, M, fp } = load(positional());
  const errs = validate(F, M);
  if (errs.length) { console.error(`check: ${errs.length} problem(s) in ${path.relative(ROOT, fp)}`); errs.slice(0, 40).forEach((x) => console.error('  ' + x)); if (errs.length > 40) console.error(`  … ${errs.length - 40} more`); process.exit(1); }
  if (!M) console.warn('check: warning: no metrics.json (signals not checked); run `mine` first');
  const recs = F.findings.flatMap((f) => f.recommendations || []);
  if (!quiet) console.log(`check: OK · ${F.findings.length} findings · ${recs.length} recommendations · ${M ? M.signals.length : 0} signals dispositioned`);
  return { F, M };
}

async function renderPDF(htmlFile, pdfFile) {
  const req = createRequire(path.join(ROOT, 'noop.js'));
  let pw = null; try { pw = req(req.resolve('playwright')); } catch {}
  const bins = [process.env.PM_BROWSER, 'chromium', 'chromium-browser', 'google-chrome', 'google-chrome-stable', 'microsoft-edge', 'brave-browser'].filter(Boolean);
  const bin = bins.map((b) => (b.includes('/') ? b : which(b))).find(Boolean);
  if (!bin && pw) {
    const browser = await pw.chromium.launch();
    try { const page = await browser.newPage(); await page.goto(pathToFileURL(htmlFile).href); await page.pdf({ path: pdfFile, preferCSSPageSize: true, printBackground: true }); } finally { await browser.close(); }
    return 'playwright';
  }
  if (!bin) throw new Error('no Chromium-family browser found. Set PM_BROWSER=/path/to/chrome, or open report.html and Print → Save as PDF');
  // Render inside a visible home subfolder: snap/flatpak browsers can't read /mnt, /tmp or hidden dirs.
  const work = fs.mkdtempSync(path.join(os.homedir(), 'pm-render-'));
  try {
    const h = path.join(work, 'report.html'), p = path.join(work, 'report.pdf');
    fs.copyFileSync(htmlFile, h);
    const sandbox = process.getuid?.() === 0 ? ['--no-sandbox'] : []; // Chrome refuses to run as root with its sandbox
    const r = spawnSync(bin, [...sandbox, '--headless=new', '--disable-gpu', '--no-first-run', '--no-pdf-header-footer', '--print-to-pdf-no-header', '--run-all-compositor-stages-before-draw', `--print-to-pdf=${p}`, pathToFileURL(h).href], { encoding: 'utf8', timeout: 120000 });
    if (!fs.existsSync(p)) throw new Error(`${bin} did not produce a PDF: ${clip(r.stderr, 300)}`);
    fs.copyFileSync(p, pdfFile);
  } finally { fs.rmSync(work, { recursive: true, force: true }); }
  return path.basename(bin);
}
```

## 12. Anti-patterns (never)

- Writing the PDF, the scores or the priorities by hand, or editing `metrics.json`.
- Findings without evidence, or "evidence" that's just a restatement of the observation.
- Auditing an observation by re-reading your own reasoning instead of the evidence, or letting the
  auditor see the conclusion before the evidence.
- Dropping rejected observations or dismissing signals in bulk ("all noise") without a reason each.
- Recommendations like "be more careful" or "communicate better" with no concrete change attached.
- Blaming the user, or soft-pedaling Claude's own mistakes.
- Pasting whole transcripts into context, or secrets and personal data into the register or report.
- Skipping the journal during the project and reconstructing Cowork sessions from guesswork afterwards.
- Editing shared ai-assets based on a post-mortem without the user's OK, or without a version bump.
- Rewriting `postmortem.mjs` per project; fixes go back into this standard with a version bump.
